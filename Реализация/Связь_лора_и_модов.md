# Сопоставление лора с технической реализацией

## Правило

Лор описывает функцию, а не конкретный мод.

Например, лор требует «город учёных», а реализация может быть:

1. полноценные NPC;
2. торговцы и терминалы;
3. квестовый объект;
4. структура с книгами и наградами.

## Формат фичи

Для каждой системы фиксируются:

- лорная функция;
- игрокоориентированный эффект;
- ранний вариант;
- полный вариант;
- fallback без нужного мода;
- зависимости;
- риск производительности;
- тест при запуске.

## Приоритеты

### Must have

- личные базы;
- поселения;
- стратегические объекты;
- базовое PvE;
- технологический прогресс;
- сохранение и резервные копии;
- управляемое разрушение.

### Should have

- специалисты;
- торговля;
- радио;
- события;
- транспорт;
- квесты;
- контролируемые роботы.

### Nice to have

- полноценные NPC-поселения;
- сложные фракционные отношения;
- динамический рост заражения;
- межмировые переходы;
- эфирные сущности.

Технические ограничения не должны ломать фундаментальный сюжет: для каждой важной функции должен быть упрощённый fallback.
